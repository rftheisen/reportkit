The workflow

Write plainly.
Deliver beautifully.

ReportKit keeps the authoring model deliberately boring: ordinary files in an ordinary repository. The polish happens at build time.

01

Write

Keep the narrative, findings, and appendices in reviewable Markdown.

findings/F-001-default-credential.md
02

Validate

Catch placeholders, missing evidence, unsafe paths, and likely secrets.

reportkit preflight assessment/
03

Build

Generate a self-contained HTML report and a polished, paginated PDF.

reportkit build assessment/
Built for the work

Everything the report needs.
Nothing it doesn’t.

Aa

Print-grade design

Cover pages, running footers, severity badges, tables, code blocks, and a paginated contents page.

✓

Delivery preflight

Automated checks find unfinished text, broken images, absolute paths, and common secret patterns.

F#

Finding discipline

Sequential finding creation and one-file-per-finding organization make review and reuse straightforward.

⌘

Evidence capture

Consistently numbered screenshot names keep proof tied to the finding it supports.

git

Collaboration by default

No proprietary document format. Use branches, pull requests, diffs, and the editor you already know.

◇

Easy to customize

Brand and reshape the output with ordinary HTML, CSS, YAML, and Markdown—without rebuilding an app.

Quick start

From clone to PDF
in three commands.

The included Northstar assessment is entirely fictional and ready to build, inspect, and use as a safe starting point.

Read the live example report →
shell 
$ git clone https://github.com/rftheisen/reportkit
$ cd reportkit
$ make preflight
Preflight passed: 0 warning(s)
$ make build
HTML: .../northstar-security-assessment.html
PDF:  .../northstar-security-assessment.pdf
